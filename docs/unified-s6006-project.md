# S6006 — ข้อมูลโครงการเดียวกัน

Issue [#5](https://github.com/saratchai1/riverbank-dam-types/issues/5) เชื่อมข้อมูลที่เคยแยกเป็นมิติหน้าตัด คาน ดิน และรายงานเข้าด้วยกัน ใช้ต่อจากการทบทวนสมการ S6006-R2 โดยไม่เปลี่ยนสมการหรือชุดข้อมูลต้นฉบับ

## การใช้งาน

1. เปิด `projects/s6006/` แล้วเลือกสถานีจาก BOQ ด้านบน
2. แก้หน้าตัดหรือค่าคาน/ดินของสถานีนั้น ลาดที่แก้จากหน้าตัดและโมดูลดินเป็นค่าเดียวกัน
3. บันทึกระดับน้ำ ที่มาระดับน้ำ หลุมเจาะอ้างอิง และข้อสมมติในส่วนบริบท หากยังไม่ยืนยันให้เว้นว่าง
4. สลับสถานีเพื่อแก้สถานการณ์อีกชุด แอปเก็บค่าของสถานีเดิมไว้
5. กด **บันทึกโครงการ JSON** ไฟล์เดียวรวมทุกสถานีที่แก้และสถานีที่เลือกอยู่ เมื่อนำไปเปิดอีกเครื่อง ผลคำนวณสร้างใหม่จากค่าตั้งต้นที่ตรวจรูปแบบแล้ว
6. กด **รายงานค่าปัจจุบัน** แอปสร้างสำเนาข้อมูลของโครงการและสถานีขณะนั้น รายงานแสดงรุ่นข้อมูล วันที่/เวลา ที่มา สมการ และค่าที่ใช้จริง การแก้โครงการภายหลังไม่เปลี่ยนสำเนารายงานเดิม

แอปเก็บงานล่าสุดในเบราว์เซอร์ด้วย หากพื้นที่จัดเก็บไม่พร้อมจะแจ้งให้บันทึก JSON การย้ายเครื่องใช้ไฟล์ JSON ส่วนการส่งรายงานให้ผู้อื่นใช้ PDF ที่พิมพ์จากรายงาน ลิงก์สำเนารายงานอ้างถึงข้อมูลในเบราว์เซอร์ที่สร้างรายงานนั้น

## ความหมายของสถานีและข้อมูลที่ยังขาด

ทะเบียน 41 สถานีมาจากชีตถอดปริมาณเดิม รหัสสถานีใช้ช่วงและแถวต้นฉบับ เช่น `r1-row14` กับ `r2-row104` จึงย้อนกลับไปยังเซลล์ต้นทางได้ แต่ยังไม่ใช่หน้าตัดสำรวจที่สร้างใหม่จาก DWG

สถานีที่ยังไม่แก้เริ่มจากรูปตัด SD-02 ค่าตัวอย่าง BF1 และตัวอย่างทรายเดิมอย่างชัดเจน ไม่มีการสร้างพิกัด ภูมิประเทศ ชั้นดิน หรือจับคู่หลุมเจาะขึ้นเอง ระดับน้ำและข้อความที่มายังว่างจนกว่าจะกรอก ค่าดินที่แก้เป็นสมมติฐานของสถานการณ์จนกว่าจะยืนยันกับข้อมูลสำรวจและวิธีทดสอบ

ความยาวในแบบจำลองคือ **ความยาวขยายรูปตัดทฤษฎี** ไม่ใช่ความยาวรับผิดชอบของแถว BOQ หน้าตัดปัจจุบันใช้ตรวจปริมาณองค์ประกอบทฤษฎี ส่วนตารางปริมาณ 41 สถานียังคำนวณซ้ำจากข้อมูลเดิมและคงช่องว่างเดิมไว้ ไม่เปลี่ยนเป็น BOQ ของแบบแก้โดยอัตโนมัติ

ระดับน้ำที่กรอกปรากฏในรูปตัดและรายงาน แต่ไม่ได้ถูกแปลงเป็นแรงดันน้ำรูพรุน โมดูลดินยังเป็นลาดอนันต์เนื้อเดียวภายใต้กรณีแห้ง/อิ่มตัวน้ำซึมขนานลาด หรือ total stress จาก Su การแก้ระดับน้ำไม่ได้อ้างว่าคำนวณเสถียรภาพรวม หรือน้ำลดฉับพลันแล้ว

## โครงสร้างไฟล์

ไฟล์ใช้ `schema: riverbank.s6006.project`, `calculationRevision: S6006-R2` และ `projectCode: S6006` พร้อม `selectedStationId` กับ `stationScenarios` รุ่นแรกเป็น version 1 ส่วนโครงการใหม่เป็น version 2 ซึ่งเพิ่มการเก็บทางเลือกใน `stationComparisons` ตาม [คู่มือเปรียบเทียบทางเลือก](s6006-alternatives.md) ไฟล์และสำเนารายงาน version 1 ยังรองรับโดยคงรหัสรุ่นข้อมูลเดิม

แต่ละสถานการณ์ที่แก้เก็บ:

| ส่วน | ข้อมูล |
| --- | --- |
| `geometry` | มิติหน้าตัดและความยาวขยายรูปตัดทฤษฎี |
| `beamInputs` | หน้าตัด เหล็ก วัสดุ cover ช่วงรองรับ ตัวคูณน้ำหนักตัวเอง และ Mu/Vu จริงที่ระบุ |
| `soilInputs` | ชนิดพารามิเตอร์ ความลึกแนวดิ่ง น้ำหนักจำเพาะ φ′, c′ หรือ Su โดยไม่เก็บลาดซ้ำ |
| `context` | ระดับน้ำสูง/ต่ำ ระดับน้ำใต้ดินอ้างอิง ที่มาระดับน้ำ หลุมเจาะอ้างอิง และข้อสมมติ |

ลาดดินอ่านจาก `geometry.slopeH` เพียงแห่งเดียว ผลคำนวณและเครื่องหมายอนุมัติไม่ถูกเก็บเป็นค่าที่เชื่อถือได้ในไฟล์ การเปิดไฟล์คำนวณผลใหม่จากข้อมูลที่ผ่านการตรวจ

ไฟล์มิติเดิม `riverbank.s6006.case` version 1 และไฟล์โครงสร้าง/ดินเดิม `riverbank.s6006.engineering` version 1/R2 เปิดได้พร้อมแจ้งการย้ายรูปแบบ ส่วนที่ไม่มีในไฟล์เดิมใช้ค่าตัวอย่างที่ระบุไว้ ไม่รวมสองไฟล์เข้าด้วยกันโดยคาดเดา ไฟล์โครงสร้างเดิมใช้เฉพาะค่าตั้งต้นและทิ้งผลคำนวณที่แคชไว้

## รุ่นข้อมูลและรายงาน

`projectRevision` เปลี่ยนเมื่อข้อมูลของสถานีใดสถานีหนึ่งเปลี่ยน การเลือกดูสถานีอื่นไม่เปลี่ยนรุ่นโครงการ `scenarioRevision` ระบุเนื้อหาสถานการณ์ที่เลือก ทั้งสองเป็นรหัสตรวจการเปลี่ยนแปลง ไม่ใช่ลายเซ็นดิจิทัลหรือการรับรองทางวิศวกรรม

รายงานจากปุ่มในแอปใช้สำเนาที่มีรหัสเฉพาะ และตรวจรุ่นโครงการ รุ่นสถานการณ์ และสถานีที่เลือกก่อนแสดงผล หากสำเนาหายหรือเสียหาย รายงานจะไม่สร้างผลแทนด้วยค่าเริ่มต้น และปิดปุ่มพิมพ์ การเปิด `report.html` โดยตรงจะแสดงป้ายชัดเจนว่าเป็น **ค่าต้นแบบอ้างอิง**

ข้อมูล Slope/W เดิมยังเป็นหลักฐานภายนอกเสมอ เมื่อแก้สถานการณ์จะแจ้งว่าต้องวิเคราะห์เสถียรภาพรวมใหม่ ไม่มีการเปลี่ยนค่า FS เดิมให้กลายเป็นผลรับรองของแอป

## ขอบเขตความถูกต้องที่คงไว้

- คานยังผ่านเงื่อนไข R2 เดิมก่อนให้กำลังดัดสำหรับเทียบ Mu: เหล็กคราก ความเครียดขั้นต่ำ และเหล็กขั้นต่ำ
- แยกกำลังเฉือนจากสมการกับขีดจำกัดที่ใช้ตรวจจริงตามเงื่อนไขปลอก
- Mu/Vu หรือ Su ที่ไม่ทราบยังเป็น `null` โดยกรณี Su ที่ยังไม่ครบไม่มีผล FS ค้างจากกรณีก่อนหน้า
- ปฏิเสธข้อมูลผิดรูปแบบ มิติที่เป็นไปไม่ได้ ตัวเลขนอกขอบเขตคำนวณ สถานีที่ไม่มี และการป้อนผลอนุมัติที่ไม่ได้คำนวณ
- ไฟล์ที่ไม่ผ่านตรวจไม่แทนที่โครงการที่ยอมรับอยู่
- ไม่มีผลอนุมัติทั้งโครงการ ไม่มี solver เสถียรภาพรวม และยังไม่รวมการวิเคราะห์ระบบคาน–เสาเข็ม–ดินครบระบบ

## การตรวจซ้ำของซอฟต์แวร์

`npm test` ตรวจการคำนวณเดิมควบคู่กับการผูกลาด การแยกค่าระหว่างสถานี การเปิด–บันทึกไฟล์ การย้ายรูปแบบเก่า การคงค่า null การตรวจรุ่นสำเนารายงาน และการแสดงค่าปัจจุบันในรายงาน

`npm run test:browser` ตรวจการแก้ค่าและสลับสถานีจริงในเบราว์เซอร์ เปิดไฟล์กลับ รายงานสำเนาปัจจุบัน การแก้งานต่อโดยรายงานเดิมไม่เปลี่ยน การระงับรายงานที่ข้อมูลหาย การแสดงผลมือถือ รวมถึงการพิมพ์ PDF และการไม่ล้นเชิงอรรถของแต่ละหน้า หลักฐานการรันแต่ละรุ่นอยู่ใน GitHub Actions ของ PR

การทดสอบเหล่านี้ยืนยันขอบเขตการทำงานของซอฟต์แวร์ ไม่แทนการตรวจสมมติฐานและรับรองแบบโดยวิศวกร
